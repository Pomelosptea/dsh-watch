# 手表端使用教程

> 适用设备：OPPO Watch X2（OWW251，466×466，Android 11 / ColorOS Watch）及 Wear OS 5 同类手表
> 对应版本：DSH Watch `1.0.0`
> 一句话原理：抬腕跟手表说话 → 指令经 ZeroTier 送到主机的桥接端口 → 主机的 DSH 执行 → 结果回到表盘。

> 文中 `<主机ZT地址>`、`<端口>`、`<令牌>` 都要换成你自己的值。示例用 `10.42.0.7` / `18787` / `change-me`。

---

## 一、先决条件（只做一次）

| 位置 | 要准备的东西 |
|---|---|
| 主机 | DSH 桌面端能正常对话；桥接已启动并监听 `<端口>`（默认 `18787`）；已加入 ZeroTier 网络 |
| 主机 | 防火墙放行 TCP `<端口>`（Private / Public 都放） |
| 手表 | 装好 ZeroTier 与 DSH Watch 两个 APK；手表也加入**同一个** ZeroTier 网络 |
| 手表 | 首次装完在 ZeroTier 里点「允许 VPN」；只走移动数据时勾上「允许移动数据」 |

主机侧确认：

```powershell
# 桥接是否在跑
Get-NetTCPConnection -State Listen -LocalPort 18787

# 桥接健康检查（免令牌）
curl http://127.0.0.1:18787/health
```

返回 `{"ok":true,"service":"dsh-watch-bridge",...}` 就算主机侧就绪。

---

## 二、第一次连接（三步）

1. **手表连 ZeroTier**
   表端 ZeroTier → 加入网络（16 位 Network ID）→ 系统弹 VPN 授权，滑到底点「确定」→ 回 ZeroTier Central 给这台设备打勾授权（Auth）→ 表盘出现 `10.x.x.x` 即成功。

2. **打开 DSH，进入主机设置**
   首次没有主机时，**点一下鲸鱼**会直接进「主机设置」；也可从设置页进入。填三项：

   | 字段 | 填什么 | 说明 |
   |---|---|---|
   | ZeroTier IP / 主机名 | `<主机ZT地址>` | 主机在 ZeroTier 里的地址，不是 Wi‑Fi 地址 |
   | 端口 | `<端口>`，默认 `18787` | 与 `bridge/config.json` 的 `port` 一致 |
   | 令牌（可留空） | `<令牌>` | 与 `bridge/config.json` 的 `token` 一致；留空则用构建时的默认值 |

3. **点「保存并测试」**
   - 「已连接，可以开始使用」→ 完成
   - 「已保存，但暂时连不上主机」→ 看第七节排查

> 也可以完全用 ADB 预置，不用在表上打字：
> ```powershell
> adb shell am start -n com.deepseek.dshwatch/.MainActivity `
>   --es dsh_host <主机ZT地址> --ei dsh_port 18787 --es dsh_token <令牌>
> ```
> 这些参数会写入手表本地配置，重启后仍生效。

## 三、主界面怎么读

顶部状态行：

| 显示 | 含义 |
|---|---|
| `未设置主机` | 还没填地址端口，点鲸鱼去设置 |
| `正在连接 · <主机>` | 正在探测桥接 `/health` |
| `主机在线 · <主机>` | 桥接可达，可以发指令 |
| `主机离线 · 消息会待命` | 暂时连不上；发出的会排队，链路恢复自动补发 |

鲸鱼下方提示语会随状态变化：

| 提示 | 含义 |
|---|---|
| `按住说话 · 点击输入` | 空闲，可长按语音或点一下打字 |
| `网络离线 · 发送会待命补发` | 离线，现在发的会进待发队列 |
| `待发送 · 等待网络` | 已入本地队列，等网络 |
| `已发送 · 等待主机接收` | 桥接已收到，还没开始执行 |
| `DSH 正在处理…`（或具体阶段文字） | 主机正在跑这一轮 |
| `收到回复 · 点记录查看` | 完成，点记录看全文 |
| `已撤回 · 点击输入新指令` | 这条被撤回了 |
| `发送失败 · 点记录查看` | 出错，记录里有原因 |

## 四、发指令的三种方式

1. **点一下鲸鱼 → 键盘输入**
   打开「输入指令」页，输入后按键盘的**发送**键（或右下角发送按钮）。单条上限 2000 字，右下角有字数计数。
2. **长按鲸鱼 → 语音**
   走系统标准 `RecognizerIntent`。识别到什么就发什么。
3. **输入法自带的麦克风**
   如果设备没有系统语音识别服务，长按会自动落到键盘输入；这时点输入法的麦克风说话，识别结果会填进输入框，再按发送。

好用的指令写法（越具体越省事）：

- 「看一下 D 盘还剩多少空间」
- 「把下载目录里超过 100MB 的文件列出来」
- 「查一下昨天那个项目的构建日志，最后 50 行」
- 「在 work 目录下建个 notes 目录，把刚才的结论写进去」
- 链路自检：「只回复两个字：收到」

> DSH 的文件/命令工具默认在桥接配置的 `workspace` 里操作。要动别处就在指令里写**绝对路径**；能不能写取决于主机上 DSH 的权限策略。

## 五、一次对话的完整流程

1. 发出后进入**对话页**：顶部是 `DSH` + 状态（`聆听中` / `执行中` / `已完成` / `出错`）。
2. 回复流式输出，页面自动滚到底；复杂任务可能要几分钟（桥接默认超时 10 分钟）。
3. 想中断：点「**停止**」，会通知桥接取消当前这一轮。
4. 看完点「**关闭**」回首页。

## 六、对话记录、离线待发、撤回

进记录页：首页右下角的**双气泡图标**，或发完消息后自动进入。

每条消息有 6 种状态：

| 状态 | 含义 |
|---|---|
| `待发送` | 只在手表本地，等网络 |
| `已发送` | 桥接已接收 |
| `执行中` | 主机正在执行，可能带当前阶段文字 |
| `完成` | 已收到回复 |
| `失败` | 出错，下面会给原因 |
| `已撤回` | 已撤回，回复不再显示 |

三个关键行为：

- **本地优先**：点发送立即落本地记录，重启手表或应用后记录还在。
- **离线待发**：断网时保持「待发送」，前台服务按 5 秒退避重试；链路恢复自动发出，不用反复点。
- **后台收信**：发完按 Home 切后台，回复仍会到（前台服务 + 事件长轮询，通知栏会显示持续收信）。

**撤回**：点消息右上角的「撤回」：

- 还没发出去 → 直接从待发队列删掉；
- 已发出 / 执行中 → 通知桥接标记撤回，并尽量取消主机上的执行；
- 已完成的 → 本地隐藏这条回复，状态变「已撤回」（主机侧历史不会被改写）。

## 七、连不上？按这个顺序查

| 现象 | 八成是 | 怎么办 |
|---|---|---|
| `主机离线` 一直不恢复 | 桥接没起 / 防火墙 | 主机上 `Get-NetTCPConnection -LocalPort 18787`；`curl http://127.0.0.1:18787/health` |
| 主机本机能访问、手表不行 | 不在同一 ZeroTier 网络 / 未授权 | 两边 `zerotier-cli listnetworks` 对比 Network ID 与 IP；Central 里给手表节点打勾 |
| 手表 ZeroTier 显示「等待授权」 | 没在 Central 授权 | Central → Members 勾选该设备 |
| 保存测试一直失败 | 填成了 Wi‑Fi 地址 | 填主机的 **ZeroTier** 地址（`10.x.x.x`），不是 `192.168.x.x` |
| 一直「正在思考…」 | 任务本身慢 | 复杂任务几分钟正常；桥接超时 10 分钟 |
| 长按鲸鱼没反应 | 固件没有语音识别服务 | 用键盘 + 输入法麦克风 |
| 提示令牌错误 | `token` 不一致 | 改 `bridge/config.json` 的 `token`，手表设置里同步改 |
| 装不上 / 与已装版本签名冲突 | 旧包签名不同 | 先卸载旧包再装 |

## 八、清理上下文

要开一段全新对话（丢掉之前的上下文）：

```powershell
curl -X POST -H "Authorization: Bearer <令牌>" http://127.0.0.1:18787/api/session/new
```

或者删掉 `bridge/state.json` 后重启桥接（会重新建 session）。手表本地聊天记录不受影响。

---

## 九、安全提醒

- 桥接是 **HTTP + Bearer token**，没有 TLS。**只在 ZeroTier 私网里用**，不要把桥接端口映射到公网。
- `token` 等于主机控制口令：谁知道它，谁就能让你的主机跑 DSH 指令。请改成随机长串，并同时改 `bridge/config.json` 与手表设置。
- 桥接以你的系统用户权限执行；`autoApprove` 默认 `false`，需要审批的工具调用不会自动放行，复杂写操作可能停在审批处。
